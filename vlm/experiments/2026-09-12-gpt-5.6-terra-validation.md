# GPT-5.6 Terra zero-shot validation probe

This is a small capability probe, not a full benchmark, an accuracy claim, or
evidence of industrial readiness.

- Dataset: DsPCBSD+, deterministic `validation` split only
- Subset: 6 images selected one-per-class where available
- Model: `gpt-5.6-terra`
- API: OpenAI Responses API, strict structured output, `store: false`
- Adapter: `pcb-zero-shot-v1`, pixel-space boxes and frozen nine-class taxonomy
- Reasoning effort: `low`
- Test split: **not run**

Observed result from the hosted run:

- 6/6 requests passed strict response validation; 0 parser failures
- 5 structured predictions were admitted across 6 images
- At class-aware IoU 0.5: 0 true positives, 5 false positives, and 13 false
  negatives
- Inference latency: mean 5,569 ms; p50 4,733 ms; p95 7,920 ms; range
  3,939–7,920 ms
- The five predicted boxes had best class-agnostic IoUs of 0.220, 0.435,
  0.669, 0.450, and 0.693 against a ground-truth box
- Two predictions used the correct class but missed the 0.5 IoU gate; three
  localized a plausible defect region but selected the wrong fine-grained
  class; one image correctly returned no fabricated box but missed its defect
- All model scores remain uncalibrated and all findings remain routed to human
  review

Interpretation: strict structured output solved the local model's response
format failure, and several boxes were spatially useful. Fine-grained PCB class
selection, box tightness, multi-defect recall, and abstention are not yet good
enough to justify running the frozen test split. The next validation experiment
should add crop verification and controlled 1/3/5-shot support examples, then
repeat this exact subset before any full evaluation.
